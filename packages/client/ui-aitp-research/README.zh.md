# AITP 科研工作台

[English](README.md) | 中文

## 概述

在同一个工作台浏览项目、课题、子方向及资料。左侧在各方向下列出实际 Harness 会话，中间保留当前阅读位置，右侧打开正常会话继续研究。仅浏览不会创建会话或发送模型请求。科研内容通过框架资源和异步适配器读取；开发示例明确标记为模拟数据，[科研后台](../ui-aitp-backend/README.md)连接获准的 Markdown 目录和实际会话。

## 使用与行为

Research 使用 Harness 已有侧栏，展示课题树及方向下的讨论。“所有会话”回到原有会话浏览器。在当前方向切换讨论时，中间资料保持不动；进入另一方向时恢复该方向的阅读位置。顶部工作区选择器沿用 Harness 工作区。资料内容由资源服务持有，侧栏、研究地图和课题页只共享界面状态。

右侧复用完整 Conversation 与 Chat 界面，包括原有输入框、模型选择、附件、队列或引导消息、流式回答、停止和审批。顶部可以切换该方向的会话、明确新建空白讨论、展开或收起右栏。打开或切换讨论期间，旧会话仍显示，但不能接收焦点、输入或提交；已有草稿仍属于原会话。讨论菜单可以重命名同一个原生会话，成功的标题事件更新列表，不改变课题绑定，也不发送输入草稿。收起保留实际会话及其输入草稿。打开讨论优先恢复已选或最近的匹配会话；新建空白讨论暂未成为科研记录，第一条研究消息成功接收后才记录课题绑定。同一个会话仍可从普通 Harness 会话列表打开。窄窗口用可关闭的覆盖面板保留同一套操作。

卸载 Research 会停止接收新的讨论打开操作，取消本插件的讨论列表读取和会话就绪等待，并在已接收的打开操作结束后释放引用。晚到的列表响应不能再创建会话或初始化输入草稿。已经发给 Host 的原生会话创建请求没有取消接口；卸载会等待其结果，但不再接管或删除返回的会话。

未接入的工作区先显示“启用研究项目”，由使用者选择只读或允许保存。浏览不会自行授权目录。只读模式不创建缺失的研究记录；可写初始化按需建立记录并保留已有内容。应用内登记的只读项目可以明确升级为允许保存，静态配置的只读授权不能在这里绕过。

可写项目可新建课题或子方向，填写标题、问题、可选范围和父级位置。创建使用后台拥有的幂等操作 ID；失败保留表单，结果不确定时检查同一次操作。草稿和未确认操作属于工作区，在当前客户端内切换课题或离开面板仍保留。有界、版本化的标签页恢复记录支持同标签页刷新；恢复后不会自动重发。成功后打开实际课题及右侧讨论，不自动向模型发送课题问题。

研究地图概览项目、研究方向、顶层课题及待探索想法；聚焦后呈现该方向的问题、对父课题的作用、带条件的当前回答、缺口、下一步和资料。课题页以回答和范围为主，管理、状态与读取详情按需展开。位置路径与返回操作连接各层，返回恢复滚动位置、焦点及已展开区域。分支、支持、证明或依赖只显示后台明确提供的记录，不根据父子关系、顺序或时间自行推断。

## 资料与讨论

课题的资料区通过 `aitp.research.topic.libraries` 扩展接入独立的文献、知识和代码插件。它们接收当前工作区、方向和标题，保留同一研究树与右侧讨论。资料的维护归属不改变明确选择的提问范围。离开时记录阅读位置，返回时恢复滚动、焦点和展开状态。Research 不在运行时导入这些资料插件；卸载一个库只撤掉该库的入口和处理器。仅全局资料浏览继续保留原有独立提问框。

当前方向、资料和明确选中的片段准备下一条消息。前进与返回会更新自动暂存的阅读来源；明确选择的资料集、锚点和片段保持优先，原 Session 与草稿不变。正常提交在命令处理和附件上传之前冻结来源，将原有请求 ID、完整消息内容及队列或引导模式一起交给后台，并继续使用当前 Session。之后浏览另一份资料不会改变已经接收的消息。提交失败保留原生输入草稿。勾选或显示资料不代表模型已读；实际交付片段由 Host 记录。

点击回答引用会在中间打开对应资料。科研资源或笔记地址必须属于同一工作区，同时保留当前问题方向；普通文件地址必须能转换为当前工作区内的规范相对路径。实际权限、文件存在性和读取范围仍由后台检查。独立资料库各自处理自己的地址类型，并保留返回课题的回调。无法打开的引用在讨论中显示错误，不会悄悄转入隐藏的资料侧栏。

## 后台适配与刷新

共享类型来自 [research-memory](../../research/research-memory/src/types.ts)，通过本包 `/client` 入口仅导出类型。浏览器提供者通过 `researchWorkspaces.register(factory)` 为明确工作区提供适配器；注册表负责提供者生命周期和变化通知。首个 Markdown 提供者采用路径身份，无法自动识别未知重命名；版本值是后台拥有的不透明观察。

| 资源协议 | 内容 |
| --- | --- |
| `aitp-workspace-setup` | 接入状态、保存权限及显式初始化能力 |
| `aitp-workspace-project` | 项目、研究方向和想法 |
| `aitp-workspace-topics` | 带父子关系和完整性说明的课题分页 |
| `aitp-workspace-topic` | 单个课题的问题、回答、工作、论断和资料 |
| `aitp-workspace-resource` | 实际资料内容或明确的不可读取状态 |
| `aitp-workspace-activity` | 记录更新、提案及后台会话引用 |
| `aitp-workspace-discussions` | 该方向的原生会话列表；省略 `topic` 查询参数表示项目根讨论 |
| `aitp-workspace-change` | 当前会话科研写入操作的有界回执和记录差异 |

会话资源调用适配器的可选 `listDiscussions`，直接返回 `DiscussionPage`。列表读取持久化绑定元数据，无需激活项目内每个会话。项目根讨论与各方向严格区分；不支持的提供者显示能力缺失，不构造假会话。

变化事件使现有资源重新读取权威内容，不向另一份正文缓存写入推测结果。后台确认的科研记录或来源修改会刷新对应读取；流式回答本身不会冒充已经保存的科学记录。断开连接时保留最后成功读取及错误状态，重连后恢复读取。

会话上方的简短更新提示读取实际科研写入工具元数据。“查看修改”才加载已认证的操作回执，并复用 Harness 差异组件展示记录中的修改前后文字。提示明确区分成功保存、部分完成、结果不确定、计划修改、被省略的详情，以及操作之后原文又发生的变化。模型声称“已经保存”本身不能产生成功保存提示。提示的指针缓存归属于各自的插件注册，重载或卸载会释放观察；同一生命周期内无关的流式更新保留指针身份。

回答和范围修改按能力调用 `previewChange` 后再 `applyChange`；条件与结论分开呈现，仅在收到成功回执后显示已应用。权限、源文件映射、幂等、冲突和恢复由后台拥有。回执丢失表示结果不确定，重试仍使用原操作 ID。

## 原有笔记视图

`aitp-topics`、`aitp-topic` 和 `aitp-note` 保留原有笔记投影，不替代新课题适配器。在普通 Harness 会话中，笔记仍可通过原侧栏打开，包括“来源与记忆”中的引用；在集成科研讨论中，引用优先回到中间阅读区。

## 限制与后续工作

- 原生输入草稿由 Session 输入服务拥有，可跨阅读面板保留。右栏选择、展开状态和阅读位置是当前客户端的界面状态，不宣称浏览器重启后恢复。
- 新建课题的恢复记录在可用的标签页存储内跨刷新保留；关闭标签页可能丢弃这份本地元数据，持久化操作所有权仍在后台。
- 路径重命名、富文本数学选区、精确行滚动、跨方向关系图仍需相应提供者支持。PDF 等读取和物理页定位由独立资料库承担。
- 消息内容、请求身份及队列或引导模式已保留。科研归因消息仍沿用现有 Host 时间回退，浏览器时区的持久化归因尚未扩展。
- 科研授权必须来自明确配置或应用接入；保存始终需要对应项目的写入权限。

## 模型体验

只有明确提交的研究问题才进入正常 Harness 会话。后台恢复当前方向的记录、选中资料和实际交付片段；浏览本身不触发模型请求。

#### KV 缓存影响

请求组装和缓存前缀仍由后台科研记忆集成拥有；前端传递明确的问题和已冻结的来源范围。
