# Design-review reproductions, 2026-10-22

Receipts for the architecture review recorded in [current.md](../../current.md) (Q01, Q02). These are
reproductions of present behaviour on the synthetic runtime fixture, not new features or fixes. The
tests assert the defective behaviour so that each observation is exact; they are kept outside the
suite, in the original worktree's git-ignored `agent/.local/review/`. These scripts are not included
in this standalone snapshot; the command below is a historical receipt, not a command available
in a fresh public clone. They must not be copied into `packages/*/test` with
these expectations. When a correction lands, invert the relevant assertion into a regression test in
the owning package.

## Command and result

Run from `agent/` under the shared heavy-process lock, one worker, faux/scripted model only:

```text
NODE_OPTIONS=--max-old-space-size=1024 flock "$AITP_HEAVY_LOCK" \
  npx vitest run --config .local/review/vitest.config.ts --reporter=verbose
 ✓ R-A: a selected source that later disappears makes every context preparation throw
 ✓ R-B: explicitly selected material is budgeted after automatic background and loses first
 ✓ R-C: compaction relabels model summaries and runtime continuations as researcher decisions; choice answers lose their meaning
 ✓ R-D: material attached to an interjection stays 'placed' after compaction but is not re-delivered
 Tests  4 passed (4)
```

No live model, real workspace, browser or application server was used. The fixture is
`packages/runtime/test/conformance/fixture.ts` with `pi-adapter/test/scripted.ts`.

## Observations

| Case | Setup | Observed |
| --- | --- | --- |
| R-A | Session scope holds a fixture note; the file is then deleted | `context.prepare` rejects with `ENOENT`. `optional()` in `runtime/src/context/index.ts` absorbs only `not_implemented`, so no partial manifest or omission is produced and the next submission or Continue fails |
| R-B | Two automatic parent-use openings fill most of the request budget; one explicitly selected file follows | `{"limit":76800,"parentStatuses":[8 × "admitted"],"selectedStatuses":["pointer"]}`. Candidates are admitted in insertion order; explicit scope is inserted after opening, Current work, plan, parents, root, knowledge, edition and checkout |
| R-C | Task → `ask_researcher` (options a "Analytic only", b "Allow numerics") → answer a → Continue → compaction → two interjections → compaction | First summary request's `researcherRequestsAndDecisions` contains `Researcher response to choice card …: {"type":"choice","option":"a"}` without the option label and `Continue the authorized task: <original request>`. The second contains Pi's previous summary (`The conversation history before this point was compacted …`) as a researcher entry |
| R-D | Task; interjection attaching a non-parent file; compaction | Manifest item for the attached file keeps status `placed`; no message after `compaction-applied` re-delivers it. Refresh after compaction uses only the active task's scope, and the active task is rebuilt from the latest `task` input |

Related source facts, read but not separately executed: `ActiveTask.nextAction` is read by
`sessions.continue()` and written nowhere; `beforeTool` blocks only from status mode and note-derived
scope flags; the execution port exposes whole-conversation `abort` but no withdrawal of one queued
submission, although Pi supports it; nothing except compaction calls `context.refresh`.

## Limits

These are deterministic runtime observations with a scripted model. They do not measure how a real
model behaves after compaction, how often budgets bind in practice, or scientific consequences.
The read-only tool registry currently has no write or execution tools, so the restriction findings
affect reasoning, continuation and future effect-capable gates rather than present file writes.
